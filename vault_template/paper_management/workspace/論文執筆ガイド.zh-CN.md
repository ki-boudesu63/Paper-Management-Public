# 论文写作指南 — 样式生成、撰写与定稿

本文件是论文管理应用"Paper Management"的 Obsidian Vault 中**撰写论文**的指南。
包含面向 AI 代理（Claude Code / Codex / Gemini CLI）的操作说明，以及面向用户的操作步骤。

撰写工作在 `workspace/` 文件夹中进行，投稿样式定义存放在 `styles/` 中。

---

## 整体流程

1. 准备目标期刊的 Author Guidelines（作者须知）
2. 【AI】根据指南生成 `styles/<期刊名>.md`（样式定义）（任务 A）
3. 【用户】复制 `原稿テンプレート.md` 并在 `workspace/` 中撰写稿件（任务 B）。
   引用可自行以 `[[链接]]` 形式插入，也可让【AI】从 `library/` 整体或指定集合中
   搜索相关论文并插入引用链接（任务 D）
4. 【AI】将稿件整理为投稿格式 — 引用编号 + 生成参考文献列表，必要时输出为 Word/LaTeX 格式（任务 C）

---

## 任务 A【AI】：生成投稿样式定义

当用户提供期刊的 Author Guidelines（文本/MD）并要求生成样式定义时：

1. 阅读指南，创建 `styles/<期刊名>.md`，格式如下：

   ```
   ---
   journal: "期刊名"
   type: style
   ---
   # <期刊名> 投稿样式

   ## 稿件类型与结构
   按稿件类型列出：章节结构（顺序）/ 字数上限 / 参考文献数上限 / 图表数上限 / 摘要格式。

   ## 正文引用格式
   例如：按出现顺序的阿拉伯数字上标（AMA 格式）/（作者，年份）等。

   ## 参考文献列表格式
   给出单条文献的格式示例。例如（AMA）：
   `AuthorAA, AuthorBB. Title. JournalAbbrev. Year;Vol(Issue):Pages.`
   注明期刊名使用缩写还是全称、作者人数上限及 et al. 的使用规则。

   ## 一般样式
   语言（美式/英式英语）、图表规则、缩写处理等。
   ```
2. 对于指南中未提及的内容，注明"指南中未说明"，不要猜测。

## 任务 B【用户】：撰写稿件

1. 将 `原稿テンプレート.md` 复制到 `workspace/` 并重命名为 `<稿件名>.md`。
2. 填写 front matter 中的 `target_journal`、`style` 和 `manuscript_type`。
3. 按照 `styles/<期刊名>.md` 中的章节结构撰写正文。
4. **在正文中以 `[[论文库中论文 MD 文件名]]` 的链接形式插入引用。**
   - 链接目标为 `library/` 中的论文 MD 文件。无需手动输入引用格式。
   - 同一篇论文可多次引用（定稿时重复引用会合并为同一编号）。
   - 如果要引用的论文不在论文库中，请先完成导入。
   - 也可以让 AI 代为搜索相关论文并插入引用链接（任务 D）。

## 任务 C【AI】：稿件投稿定稿

当用户要求对 `workspace/<稿件>.md` 进行定稿时：

1. 从稿件 front matter 中识别目标期刊，读取 `styles/<期刊名>.md`。
2. 提取正文中所有 `[[...]]` 链接中**指向 `library/` 论文 MD 的部分**作为引用
   （排除指向 `wiki/` 概念页面等非引用链接）。
3. 按**正文中首次出现的顺序编号**（同一论文的重复引用使用相同编号）。
4. 将每个 `[[链接]]` 替换为样式定义中规定的**正文引用格式**。
5. 根据每篇被引论文的 **MD front matter**（`authors` / `title` / `journal` /
   `journal_abbrev` / `year` / `volume` / `issue` / `pages` / `doi`），
   按照样式定义的**参考文献列表格式**生成参考文献列表，输出到"References"章节。
6. 如果超出样式定义中规定的字数、参考文献数或图表数上限，予以提示。
7. 将结果输出为**新文件**（例如 `workspace/<稿件>_final.md`），
   保留含 `[[链接]]` 的草稿（以便重新定稿）。
8. **如果目标期刊要求 Word（.docx）或 LaTeX 格式**，则将排版后的稿件
   转换为相应格式（由 AI 代理执行，而非应用本身）。
   - LaTeX：直接生成 `.tex` 文件（正文、章节、引用和参考文献列表均使用 LaTeX 记法）。
   - Word：如果环境中有 `pandoc` 等转换工具，则转换为 `.docx`。如果没有，
     以排版后的 Markdown 作为最终成果，并提供转换说明
     （例如：`pandoc <稿件>_final.md -o <稿件>.docx`）。

## 任务 D【AI】：搜索相关论文并插入引用链接

当用户要求"为我正在撰写的稿件搜索匹配的论文并插入引用链接"时：

1. 读取目标稿件 `workspace/<稿件>.md`。
2. **确认搜索范围**：
   - 如果未指定，则搜索 `library/` 中的所有论文 MD。
   - 如果指定了集合名称（例如"从 <集合名> 中"），则读取 `library/.collections/` 中的
     **所有 YAML 文件**，找到 `name` 字段与指定名称匹配的集合
     （YAML 文件名为 UUID，因此无法通过集合名称直接定位文件）。
     仅搜索该集合 YAML 中记录的论文（PaperId）所对应的 `library/` 论文 MD。
   - `.collections/` 位于 `config.yaml` 中 `library_root` 的直接子目录下。
3. 针对稿件中应以引用支撑的每处论述（主张、背景、与先行研究的比较等），
   从搜索范围内的论文 MD（`title` / `abstract` / 正文 / `tags`）中判断关联性较强的论文。
4. 在适当位置插入 `[[论文库中论文 MD 文件名]]` 引用链接。
   - 对于已有引用链接的论述，不重复插入。
   - 关联性不确定时不插入（优先保证精度，不增加无关引用）。
   - 链接插入在相关语句之后。**不修改稿件的论点和文字，仅添加链接。**
5. 简要报告在哪些论述处插入了哪些论文的引用链接。

插入完成后，通过任务 C（投稿定稿）进行编号和参考文献列表生成。

## 严格规则

- 不得修改稿件的论点和数据。仅进行排版工作（引用转换、参考文献列表生成、格式调整）。
- 不得删除草稿（`[[链接]]` 版本）。定稿必须输出为单独文件。
- 以论文库论文 MD 的 front matter 为文献信息的权威来源。如有缺失，予以提示。
- 不得修改 PDF 及论文库中的论文 MD 本身（只读）。
