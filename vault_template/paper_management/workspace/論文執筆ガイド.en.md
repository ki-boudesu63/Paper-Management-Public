# Paper Writing Guide — Style Generation, Writing, and Finalization

This guide covers the workflow for **writing papers** in the Paper Management Obsidian Vault.
It includes instructions for both AI agents (Claude Code / Codex / Gemini CLI) and human users.

Writing is done in the `workspace/` folder, and journal submission style definitions are stored in `styles/`.

---

## Overall Workflow

1. Prepare the Author Guidelines of the target journal
2. **[AI]** Generate `styles/<JournalName>.md` (style definition) from the guidelines (Task A)
3. **[User]** Copy `原稿テンプレート.md` and write the manuscript in `workspace/` (Task B).
   Insert citations as `[[links]]` yourself, or have the **[AI]** search `library/` or a specific collection for related papers and insert citation links (Task D)
4. **[AI]** Finalize the manuscript for submission — number citations, generate the reference list, and optionally output in Word/LaTeX format (Task C)

---

## Task A [AI]: Generate Journal Submission Style Definition

When the user provides the Author Guidelines (text/MD) of a journal and requests style generation:

1. Read the guidelines and create `styles/<JournalName>.md` in the following format:

   ```
   ---
   journal: "Journal Name"
   type: style
   ---
   # <Journal Name> Submission Style

   ## Manuscript Types and Structure
   For each manuscript type: section structure (order) / word limit / reference limit / figure-table limit / abstract format.

   ## In-Text Citation Format
   e.g.: Sequential Arabic numerals, superscript (AMA style) / (Author, Year), etc.

   ## Reference List Format
   Provide a sample entry. Example (AMA):
   `AuthorAA, AuthorBB. Title. JournalAbbrev. Year;Vol(Issue):Pages.`
   Specify whether journal names should be abbreviated or full, the maximum number of authors, and how et al. is handled.

   ## General Style
   Language (US/UK English), figure/table rules, abbreviation conventions, etc.
   ```
2. For any items not addressed in the guidelines, write "Not specified in guidelines" rather than guessing.

## Task B [User]: Writing the Manuscript

1. Copy `原稿テンプレート.md` into `workspace/` and rename it to `<ManuscriptName>.md`.
2. Fill in `target_journal`, `style`, and `manuscript_type` in the front matter.
3. Write the body text following the section structure in `styles/<JournalName>.md`.
4. **Insert citations in the body text as `[[library paper MD file name]]` links.**
   - Link targets are paper MDs in `library/`. No need to manually format citations.
   - The same paper can be cited multiple times (duplicates are merged into a single number during finalization).
   - If a paper you want to cite is not in the library, import it first.
   - Instead of searching yourself, you can have the AI find related papers and insert citation links (Task D).

## Task C [AI]: Finalize Manuscript for Submission

When the user requests finalization of `workspace/<Manuscript>.md`:

1. Identify the target journal from the manuscript front matter and read `styles/<JournalName>.md`.
2. Extract all `[[...]]` links in the body text that **point to paper MDs in `library/`** as citations
   (exclude links to concept pages in `wiki/` or other non-citation links).
3. **Number citations in order of first appearance** in the text (repeated citations of the same paper receive the same number).
4. Replace each `[[link]]` with the **in-text citation format** specified in the style definition.
5. Using the **MD front matter** of each cited paper (`authors` / `title` / `journal` /
   `journal_abbrev` / `year` / `volume` / `issue` / `pages` / `doi`),
   generate the reference list in the **reference list format** from the style definition, and output it under "References."
6. Flag any violations of word, reference, or figure/table limits specified in the style definition.
7. Output the result as a **new file** (e.g., `workspace/<Manuscript>_final.md`),
   preserving the draft with `[[links]]` intact (to allow re-finalization).
8. **If the target journal requires Word (.docx) or LaTeX format**, convert the formatted manuscript
   to that format (this is performed by the AI agent, not the app).
   - LaTeX: Generate a `.tex` file directly (body, sections, citations, and reference list in LaTeX notation).
   - Word: If a conversion tool such as `pandoc` is available, convert to `.docx`. Otherwise,
     provide the formatted Markdown as the final deliverable and include conversion instructions
     (e.g., `pandoc <Manuscript>_final.md -o <Manuscript>.docx`).

## Task D [AI]: Find Related Papers and Insert Citation Links

When the user asks to "find papers that match my manuscript and insert citation links":

1. Read the target manuscript `workspace/<Manuscript>.md`.
2. **Confirm the search scope**:
   - If not specified, search all paper MDs in `library/`.
   - If a specific collection is named (e.g., "from <CollectionName>"), read **all YAML files
     in `library/.collections/`** and find the collection whose `name` field matches the specified name
     (YAML file names are UUIDs, so collections cannot be looked up directly by name).
     Restrict the search to the paper MDs in `library/` that correspond to the papers (PaperIds)
     listed in the matching collection YAML.
   - `.collections/` is located directly under `library_root` in `config.yaml`.
3. For each statement in the manuscript that should be supported by a citation (claims, background,
   comparisons with prior work, etc.), identify strongly related papers from the target scope
   by examining their MD content (`title` / `abstract` / body / `tags`).
4. Insert `[[library paper MD file name]]` citation links at appropriate locations.
   - Do not duplicate links for statements that already have citations.
   - Do not insert links when the relevance is uncertain (prioritize precision over recall).
   - Place links immediately after the relevant sentence. **Do not alter the manuscript's claims or text — only add links.**
5. Provide a brief report of which citation links were added to which statements.

After insertion, proceed to Task C (finalization) for numbering and reference list generation.

## Strict Rules

- Do not alter the manuscript's claims or data. Focus solely on formatting (citation conversion, reference list generation, and style compliance).
- Do not delete the draft (`[[link]]` version). Always output the finalized version as a separate file.
- Treat the front matter of library paper MDs as the authoritative source for bibliographic information. Flag any missing data.
- Do not modify PDFs or library paper MDs themselves (read-only).
