# 論文執筆ガイド — スタイル生成・執筆・仕上げ

このファイルは、論文管理アプリ「Paper Management」の Vault で**論文を執筆する**ための
ガイドです。AIエージェント（Claude Code / Codex / Gemini CLI）向けの指示と、
利用者向けの手順をまとめています。

執筆作業は `workspace/` フォルダで行い、投稿スタイル定義は `styles/` に置きます。

---

## 全体の流れ

1. 投稿先雑誌の Author Guidelines（著者向け規定）を用意する
2. 【AI】ガイドラインから `styles/<雑誌名>.md`（スタイル定義）を生成する（タスクA）
3. 【利用者】`原稿テンプレート.md` をコピーして `workspace/` で執筆する（タスクB）。
   引用は自分で `[[リンク]]` を張るか、【AI】に `library` 全体／指定コレクションから
   関連論文を探させてリンク挿入させる（タスクD）
4. 【AI】原稿を投稿用に仕上げる ― 引用の番号付け＋文献リスト生成、必要に応じて Word/LaTeX 形式で出力（タスクC）

---

## タスクA【AI】: 投稿スタイル定義の生成

利用者から雑誌の Author Guidelines（テキスト/MD）を渡され、スタイル生成を依頼されたら:

1. ガイドラインを読み、`styles/<雑誌名>.md` を作成する。形式:

   ```
   ---
   journal: "雑誌名"
   type: style
   ---
   # <雑誌名> 投稿スタイル

   ## 原稿種別と構成
   原稿種別ごとに: セクション構成（順序）／語数上限／文献数上限／図表数上限／抄録の形式。

   ## 本文中の引用形式
   例: 出現順のアラビア数字・上付き（AMAスタイル）／(著者, 年) など。

   ## 文献リストの形式
   1件分の書式を例示する。例（AMA）:
   `著者AA, 著者BB. タイトル. 雑誌略名. 年;巻(号):頁.`
   雑誌名は略称か正式名か、著者人数の上限と et al. の扱いも明記する。

   ## 一般スタイル
   言語（US/UK英語）・図表ルール・略語の扱い 等。
   ```
2. ガイドラインに記載のない点は推測で埋めず「ガイドライン記載なし」と明記する。

## タスクB【利用者】: 原稿の執筆

1. `原稿テンプレート.md` を `workspace/` にコピーし `<原稿名>.md` にリネームする。
2. フロントマターの `target_journal` `style` `manuscript_type` を埋める。
3. 対象雑誌の `styles/<雑誌名>.md` のセクション構成に従って本文を書く。
4. **引用は本文中に `[[ライブラリ論文のMDファイル名]]` のリンクで挿入する**。
   - リンク先は `library/` の論文MD。引用書式の手入力は不要。
   - 同じ論文を複数回引用してよい（仕上げ時に同一番号へまとめられる）。
   - 引用したい論文がライブラリに無ければ、先に取り込んでおく。
   - 自分で探す代わりに、AIに関連論文を探させてリンク挿入させることもできる（タスクD）。

## タスクC【AI】: 原稿の投稿用仕上げ

利用者から `workspace/<原稿>.md` の仕上げを依頼されたら:

1. 原稿フロントマターから対象雑誌を特定し、`styles/<雑誌名>.md` を読む。
2. 原稿本文中の `[[…]]` リンクのうち **`library/` の論文MDを指すもの**を引用として抽出する
   （`wiki/` の概念ページ等へのリンクは引用ではないので除外する）。
3. 引用を**本文初出順に番号付け**する（同一論文の再引用は同じ番号）。
4. 各 `[[リンク]]` を、スタイル定義の**本文中の引用形式**に置換する。
5. 引用された各論文の **MDフロントマター**（`authors` / `title` / `journal` /
   `journal_abbrev` / `year` / `volume` / `issue` / `pages` / `doi`）から、
   スタイル定義の**文献リスト形式**で参考文献リストを生成し「References」に出力する。
6. スタイル定義の語数・文献数・図表数の上限を超過していれば指摘する。
7. 結果は**新規ファイル**（例 `workspace/<原稿>_final.md`）として出力し、
   `[[リンク]]` 付きの下書きは残す（再仕上げできるようにするため）。
8. **投稿先が Word（.docx）または LaTeX 形式を要求する場合**は、整形済み原稿を
   その形式に変換して出力する（アプリではなくAIエージェントが行う）。
   - LaTeX: `.tex` ファイルを直接生成する（本文・セクション・引用・文献リストをLaTeX記法で）。
   - Word: `pandoc` 等の変換ツールが使える環境では `.docx` に変換する。使えない場合は
     整形済みMarkdownを最終成果物とし、変換手順（例: `pandoc <原稿>_final.md -o <原稿>.docx`）を案内する。

## タスクD【AI】: 関連論文の探索と引用リンクの挿入

利用者から「執筆中の原稿に合う論文を探してリンクを張って」と依頼されたら:

1. 対象の原稿 `workspace/<原稿>.md` を読む。
2. **探索範囲**を確認する:
   - 指定がなければ `library/` 全体の論文MDを対象にする。
   - 「<コレクション名> から」と指定された場合は、`library/.collections/` 内の
     **全YAMLファイルを読み、`name` フィールドが指定名と一致するコレクション**を探す
     （YAMLのファイル名はUUIDなので、コレクション名では直接ファイルを引けない）。
     一致したコレクションのYAMLに記録された論文（PaperId）に対応する `library/` の
     論文MDのみを対象にする。
   - `.collections/` は `config.yaml` の `library_root` 直下にある。
3. 原稿の各記述（主張・背景・先行研究との比較など、引用で裏付けるべき箇所）について、
   対象範囲の論文MD（`title` / `abstract` / 本文 / `tags`）から関連の強い論文を判定する。
4. 適切な箇所に `[[ライブラリ論文のMDファイル名]]` の引用リンクを挿入する。
   - 既に引用リンクがある記述には重複して張らない。
   - 確信の持てない関連は張らない（精度優先・無関係な引用を増やさない）。
   - リンクは該当する文の直後に挿入する。**原稿の主張・文章は書き換えず、リンク追加のみ**行う。
5. どの記述にどの論文のリンクを張ったかを簡潔に報告する。

挿入後、タスクC（投稿用仕上げ）で番号付け・文献リスト生成を行う。

## 厳守ルール

- 原稿の主張・データを改変しない。整形（引用変換・文献リスト生成・体裁）に徹する。
- 下書き（`[[リンク]]` 版）は消さない。仕上げは必ず別ファイルに出力する。
- 書誌情報はライブラリ論文MDのフロントマターを正とする。不足があれば指摘する。
- PDF・ライブラリの論文MD自体は書き換えない（読み取り専用）。
